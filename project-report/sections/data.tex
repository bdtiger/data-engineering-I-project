\section{Data Format \& Characteristics}
\label{sec:data}

\subsection{Storage Format and Justification}
The dataset consists of New York City Taxi Trip records stored in Apache Parquet. This columnar format was chosen over row-based alternatives like CSV to enable high compression and minimize I/O overhead. Such efficiency is critical for large-scale processing within the 100~GB storage quota of the OpenStack cluster.

\subsection{Dataset Scale and Volume}
The raw dataset comprises 144 Parquet files (2014--2025). After cleaning, the operational dataset yields 219,107,040 valid records. For this project's scope, a 10--20~GB subset is processed, as summarized in Table~\ref{tab:dataset}.

\subsection{Schema Structure and Resource Constraints}
To bypass the 25~GB per-VM storage limit and conserve memory, the ETL pipeline prunes the raw TLC schema from 20 attributes to four essential columns:
\begin{itemize}
    \item \texttt{pickup\_datetime}: Engagement timestamp.
    \item \texttt{PULocationID}: TLC Taxi Zone ID.
    \item \texttt{fare\_amount}: Calculated trip fare.
    \item \texttt{pickup\_hour}: A derived attribute for hourly aggregation.
\end{itemize}

\subsection{Data Quality Challenges and Remediation}
Significant schema volatility was encountered during ingestion. Specifically, the \texttt{Airport\_fee} column shifted data types between \texttt{INT32} and \texttt{FLOAT64} across months, causing PySpark schema merge exceptions. To resolve this, the pipeline was re-engineered to read files individually and apply explicit type casting. Additionally, strict filtering was implemented to eliminate logically invalid records, such as trips with zero or negative fares, missing location IDs, or zero passengers, ensuring data integrity prior to aggregation.
